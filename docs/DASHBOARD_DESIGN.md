# طراحی و نگه‌داری داشبورد — ۲۰۲۶-۰۹-۰۵

این نسخه ادامهٔ سورس پایدار کال‌سنتر با پایگاه دانش متنی/فایلی است. مبنای آن `edfc0bb`
و اصلاح ارسال تکراری لید `4f64cb0` است؛ نسخهٔ سؤال‌وجواب در این شاخه وارد نشده است.

## تصمیم‌های طراحی

| بخش | قرارداد |
| --- | --- |
| پس‌زمینه و سطوح | بوم سرد `#f6f7fb`، سطح سفید، خط `#e6e8f0` |
| رنگ اصلی | `#635bdf`، انتخاب فعال `#eeedfb`، متن `#202337` |
| قلم | Vazirmatn محلی، وزن ۴۰۰ تا ۸۰۰؛ بدون درخواست فونت به CDN |
| هندسه | پنل ۱۶px، ورودی و دکمه ۱۰px، فاصله اصلی ۲۰ تا ۳۶px |
| محتوا | RTL؛ شماره و داده مناسب با `bdi` یا `dir=ltr` |
| آیکون | Lucide با stroke نزدیک ۱٫۷۵؛ هر آیکون یک معنای مشخص دارد |
| موبایل | منوی کشویی زیر ۱۰۲۴px؛ چیدمان تک‌ستونه پنل‌ها زیر ۷۶۰px |

مالک پوسته `DashboardLayout.tsx` و مالک قواعد مشترک `workspace.css` است. اجزای `Button`،
`TextInput` و `Card` در `components/ui.tsx` باقی مانده‌اند تا فرم‌های قدیمی هم از همان
سیستم استفاده کنند. CSS جدید بعد از `index.css` وارد می‌شود و بخش اعظم آن به
`.workspace-shell` و `.workspace-content` محدود است.

## داده و رفتار

- صفحه اصلی تنها از `/api/me` و وضعیت فایل آموزش استفاده می‌کند. نمودار مصنوعی، تعداد
  تماس زندهٔ ساختگی یا درصد ساختگی اضافه نشده است. سهمیهٔ نامحدود با ∞ نمایش داده می‌شود؛
  حساب فاقد سهمیهٔ مشخص، درصد مصرف حدسی دریافت نمی‌کند.
- برند و آواتار از همان API فعلی خوانده می‌شوند. آیکون جایگزین فقط زمانی است که لوگوی
  بارگذاری‌شده موجود نباشد.
- تمام قراردادهای ذخیره دانش، خوشامد، گوینده، کاربران و دموها حفظ شده‌اند. بارگذاری
  فقط txt/docx تا ۱۰۰KB و متن حداکثر ۲۰۰۰ کاراکتر را می‌پذیرد.
- `Button` در حالت `loading` همیشه disabled است؛ `props.disabled=false` نباید قفل
  بارگذاری را باز کند. دکمه انتخاب گوینده و دکمه پخش، هم‌سطح‌اند و داخل هم قرار نمی‌گیرند.
- تب مدیریتی در `/admin?tab=users` و موارد مشابه قابل لینک و قابل بازگشت با Back است.
  `/admin` به بخش دموها می‌رود. محافظ نقش در سمت کلاینت و سرور حفظ شده است.
- جست‌وجوی تماس روی لیست دریافتی فعلی و با نرمال‌سازی ارقام فارسی انجام می‌شود؛ فیلتر
  جدید ادعای جست‌وجوی کل آرشیو خارج از پاسخ API ندارد.
- نمایش خودکار راهنما همچنان به `HasCompletedTour` سرور وابسته است. راهنما و منوی موبایل
  تلهٔ فوکوس متداخل ندارند. Escape منو را می‌بندد و فوکوس را به دکمه منو برمی‌گرداند.
- حالت خطا و فهرست خالی در گزارش تماس متمایزند و سوالات بی‌پاسخ پس از خطا قابل تلاش
  مجدد هستند. سوال طولانی بدون truncate قابل خواندن است.

## کنترل کیفیت انجام‌شده

خروجی production با Playwright و Chrome headless بررسی شد؛ مهارت Browser در نشست موجود
نبود. داده‌ها و پاسخ‌های mutation در محیط تست mock شده‌اند و هیچ فرم QA دادهٔ مشتری را
تغییر نداده است. این آزمون‌ها تست UI هستند، نه آزمون مجدد سرویس TTS یا تماس تلفنی.

- ۳۷ بررسی: صفحه اصلی، دانش، صدا، تماس‌ها، تلفن، پروفایل، راه‌اندازی و تمام ۱۳ بخش مدیریت.
- عرض‌های ۱۵۳۶، ۷۶۸، ۳۹۳ و ۳۶۰؛ نبود صفحه سفید، overlay فریم‌ورک و overflow سند.
- ذخیره دانش، قفل loading، خطای provider شبیه‌سازی‌شده، رد فایل نامعتبر؛ انتخاب و
  پخش/توقف نمونه‌صدا و ذخیره گوینده؛ جست‌وجوی تماس با رقم فارسی و فیلتر پاسخ؛ بازکردن
  سوالات بی‌پاسخ؛ جست‌وجو و بازکردن ویرایش کاربر؛ مراحل دانش و صدای ویزارد؛ منوی موبایل؛
  اجرای راهنما در اولین ورود و عدم تکرار پس از ثبت تکمیل.
- Console بدون خطای مرتبط؛ `npm ci`، `npm run build` و `npm run lint` موفق. Lint فقط
  warning موجود مربوط به تابع مشترک `cn` در فایل کامپوننت‌ها دارد.
- وابستگی‌های lockfile مبنا حفظ شده‌اند؛ `npm ci` چهار آسیب‌پذیری high موجود در درخت
  وابستگی را گزارش می‌کند که بررسی/ارتقای آن‌ها کار مستقل از بازطراحی ظاهری است.

## بازبینی با طرح مرجع

دو مرجع تصویری برای نمای کلی و فرم/جدول پیش از کدنویسی تولید و همراه screenshots نهایی
با `view_image` بررسی شدند. اندازه مرجع ۱۵۳۶×۱۰۲۴ بود؛ screenshot کامل ممکن است footer
زیر همان viewport را نیز نشان دهد.

| نقطه مقایسه | نتیجه |
| --- | --- |
| ساختار | منوی سمت راست، هدر کم‌ارتفاع، وضعیت تلفن، سه شاخص، دو پنل و پروفایل حفظ شد |
| رنگ | سطح سفید، بوم سرد و انتخاب بنفش روشن مطابق جهت طراحی |
| تایپوگرافی | قلم محلی، تیتر خوانا و اندازه کنترل‌ها تنظیم؛ نوشته‌های ریز تقویت شدند |
| فاصله‌ها | ارتفاع اضافه پنل‌ها و فاصله‌های زائد دور دوم بازبینی کاهش یافت |
| فرم و جدول | دکمه/ورودی مشترک، وضعیت‌های آرام و جداکننده ردیف‌ها؛ وضعیت دانش داخل همان پنل |
| واکنش‌گرایی | پنل‌ها در موبایل عمودی، منوی مدیریت اسکرول افقی، جدول در ظرف اسکرول مستقل |

تفاوت‌های عمدی با mockup: داده‌های واقعی جای داده مرجع می‌نشینند؛ نمودار مدیر نامحدود
است؛ لوگوی بارگذاری‌شدهٔ فعلی حفظ می‌شود؛ جدول نمونه مرجع صرفاً در صفحه تماس‌هاست و
به صفحه دانش اضافه نشده؛ ترتیب شاخص‌ها با اولویت راست‌به‌چپ محصول چیده شده است.
متن محدودیت‌ها و footer برای حفظ راهنمای کاربردی محصول اضافه شده‌اند. تصویر mockup
بخشی از رابط اجرایی نیست؛ همه کنترل‌ها و نوشته‌ها در React پیاده شده‌اند.
