## فعال‌سازی OTP پیامکی برای ورود — ۲۰۲۶-۰۸-۱۳

- مسیر اصلی `POST /api/auth/request-otp` اکنون کد ورود را با متد Verify پنل `SMS.ir` ارسال می‌کند؛ کلید API و شناسه قالب از تنظیمات رمزنگاری‌شده پنل سوپرادمین خوانده می‌شوند.
- مسیر `POST /api/auth/request-otp-call` مستقل باقی مانده و در صفحه ورود به‌عنوان گزینه جایگزین «تماس مجدد» در دسترس است.
- محدودیت ۶۰ ثانیه‌ای میان درخواست‌ها برای هر دو مسیر مشترک است و پاسخ `Retry-After` و شمارش معکوس رابط کاربری حفظ شده‌اند.
- تصاویر `api` و `web` بازسازی و منتشر شدند. تست واقعی پیامک برای شماره ماسک‌شده با HTTP `200` و پاسخ موفق پنل پیامکی انجام شد؛ هیچ کد OTP یا کلید محرمانه‌ای در این سند ثبت نشده است.
- ۴۱ تست backend، ساخت production رابط وب، health check داخلی API و وب، و policy اجرای خودکار `unless-stopped` موفق بودند. سرویس systemd نیز `enabled` و `active` است.
- دیتابیس و volumeهای کاربران بازسازی یا حذف نشدند. شمار داده‌های اصلی قبل و بعد از انتشار ثابت ماند: ۱۶ کاربر، ۱۱ تلفن هوشمند، ۱۱ پایگاه دانش، ۱۱۷ chunk و ۵۶ تماس؛ فقط یک رکورد OTP جدید برای تست واقعی افزوده شد.

بکاپ فایل‌های تغییرکرده و tag تصاویر قبلی برای rollback پیش از انتشار در مسیر زیر نگه‌داری می‌شود:

## اصلاح مسیر ورود و OTP — ۲۰۲۶-۰۸-۱۳

- علت خطای ورود، نگه‌داشتن IP قدیمی کانتینر `api` توسط Nginx کانتینر `web` پس از بازسازی API بود؛ درخواست‌های `/api/*` با `502 Bad Gateway` متوقف می‌شدند و به سرویس OTP نمی‌رسیدند.
- پراکسی وب اکنون نام سرویس `api` را با DNS داخلی Docker (`127.0.0.11`) به‌صورت دوره‌ای resolve می‌کند؛ بنابراین تغییر IP کانتینر API دیگر ورود را از کار نمی‌اندازد.
- تصویر `web` بازسازی و روی سرور منتشر شد. مسیرهای `/health`، اطلاعات برند و درخواست OTP از آدرس داخلی و دامنه عمومی با HTTP `200` آزمایش شدند.
- سرویس‌های `arka-call-center.service` و `code-sender-with-phone.service` فعال‌اند و policy کانتینر وب `unless-stopped` است؛ داده‌ها و volumeهای دیتابیس و uploads تغییری نکردند.
- در تست واقعی، درخواست OTP از API با موفقیت `202` در سرویس تماس پذیرفته و به Asterisk تحویل شد. اپراتور SIP برای شماره آزمایشی وضعیت `BUSY` برگرداند؛ این وضعیت مربوط به مقصد/اپراتور تماس است و با خطای قبلی پراکسی تفاوت دارد.

## انتشار جست‌وجوی Hybrid RAG — ۲۰۲۶-۰۸-۱۱

- بازیابی پایگاه دانش از حالت امتیاز semantic با boost کوچک خارج شد و اکنون سه سیگنال مستقل را ترکیب می‌کند: cosine مدل `text-embedding-3-large`، امتیاز واژگانی BM25 و Reciprocal Rank Fusion.
- نرمال‌سازی فارسی، شباهت واژه‌ها و گروه‌های مترادف رایج مانند «هزینه/تعرفه/قیمت»، «آدرس/نشانی»، «ثبت‌نام/عضویت» و «گارانتی/ضمانت» به بازیابی واژگانی اضافه شد.
- امتیاز BM25 به پوشش کل مفاهیم سؤال وابسته است؛ بنابراین یک واژه عمومی به‌تنهایی باعث پذیرش محتوای نامرتبط نمی‌شود.
- ۴۱ تست backend موفق شدند. تست زنده روی chunkهای واقعی داخلی `2` سه سؤال بازنویسی‌شده درباره نقش بیمه مرکزی، شکایت و توان پرداخت خسارت را مرتبط تشخیص داد و سؤال نامرتبط «قیمت لپ‌تاپ چقدر است؟» را رد کرد.
- فقط کانتینر `realtime` بازسازی شد؛ تعداد کاربران، تلفن‌ها، پایگاه‌های دانش و chunkها قبل و بعد انتشار بدون تغییر باقی ماند.
- تست AudioSocket داخلی `2` پس از انتشار موفق بود و اولین صدای قابل‌شنیدن در `91ms` دریافت شد.

## راه‌اندازی خودکار پس از reboot

واحد systemd با نام `arka-call-center.service` روی سرور نصب، فعال و با restart کنترل‌شده
تست شده است. این واحد بعد از آماده‌شدن شبکه و Docker، استک Compose را از مسیر
`/opt/arka-call-center` بالا می‌آورد. نمونه قابل نصب آن در
[`systemd/arka-call-center.service`](../systemd/arka-call-center.service) نگهداری می‌شود.

وضعیت مورد انتظار:

```bash
systemctl is-enabled arka-call-center.service  # enabled
systemctl is-active arka-call-center.service   # active
```

## مدیریت سوپرادمین‌ها

در تب «کاربران» پنل سوپرادمین امکان ایجاد حساب مدیریتی با شماره موبایل و ارتقای کاربر
موجود به نقش `SuperAdmin` اضافه شده است. حساب جدید با همان فرایند OTP وارد می‌شود و
کاربر ارتقایافته برای دریافت claim نقش جدید باید یک بار دوباره وارد سامانه شود.

APIهای متناظر فقط با نقش `SuperAdmin` قابل فراخوانی‌اند:

```text
POST /api/admin/users/super-admins
PUT  /api/admin/users/{id}/role
```

ایجاد/ارتقای نقش در لاگ عملیاتی API ثبت می‌شود. پنل همچنین از غیرفعال‌کردن حساب
سوپرادمین جاری و آخرین سوپرادمین فعال جلوگیری می‌کند.
