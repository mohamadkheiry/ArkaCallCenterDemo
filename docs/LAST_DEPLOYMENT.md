- پخش فایل ضبط‌شده و صوت سؤال بی‌پاسخ با دریافت Blob احراز هویت‌شده، کنترل نوع/اندازه و نمایش خطای قابل‌فهم اصلاح شد. تست زنده فایل ضبط‌شده‌ی `883564` بایتی و صوت سؤال بی‌پاسخ `127244` بایتی را به‌عنوان WAV معتبر دریافت کرد؛ ۴۸ فایل ضبط‌شده‌ی موجود نیز بررسی شدند و فایل WAV نامعتبر یافت نشد.
- سؤال‌هایی مانند «من با کجا تماس گرفته‌ام؟» پیش از RAG تشخیص داده می‌شوند و نام کسب‌وکار همان داخلی را در پاسخ اعلام می‌کنند؛ سؤال‌های واقعی مثل آدرس یا ساعت کاری همچنان به پایگاه دانش می‌روند.
- timeout کلاینت OpenAI برای تولید صوت از ۶۰ به ۱۲۰ ثانیه افزایش یافت تا تولید صوت فارسی طولانی به‌اشتباه قطع نشود.
- migration راهنمای اولین ورود اجرا شد و شمار داده‌ها پس از انتشار بدون حذف باقی ماند: ۱۵ کاربر، ۱۰ تلفن هوشمند، ۱۰ پایگاه دانش، ۷۵ chunk، ۴۶ تماس و ۱۴۶ رکورد OTP.
- آزمون‌های خودکار backend: `30 passed`؛ build رابط وب، اعتبارسنجی Compose و health check سرویس‌های وب/API نیز موفق بودند.

## وضعیت آخرین انتشار مکالمه هوشمند و RAG

- ایمیج‌های `api`، `realtime` و `web` با revision برابر `940ce28` منتشر شدند.
- مدل فعال و پیش‌فرض Embedding برابر `text-embedding-3-large` است.
- هنگام warmup تعداد chunkهای دانش از ۷۴ به ۷۵ رسید؛ هیچ کاربر، تلفن هوشمند یا پایگاه دانشی حذف نشد.
- سلام، احوال‌پرسی، تشکر، عذرخواهی، تأیید کوتاه و خداحافظی بدون ورود به RAG پاسخ مؤدبانه می‌گیرند؛ سؤال ترکیبی همچنان به RAG می‌رود.
- اگر پاسخ واقعاً در پایگاه دانش نباشد، پیام استاندارد ارجاع به کارشناسان و اپراتورها پخش می‌شود.
- بازیابی فارسی از امتیاز ترکیبی معنایی و واژگانی نرمال‌شده استفاده می‌کند.
- ذخیره پیام خوش‌آمد، فایل WAV را با صدای انتخاب‌شده یک‌بار تولید می‌کند؛ تماس‌ها این فایل ثابت را کامل و پیش از اتصال Realtime/VAD پخش می‌کنند.
- همه ۱۰ تلفن هوشمند فعال پس از انتشار دارای مسیر WAV ثابت معتبر هستند؛ سه MP3 قدیمی بدون تغییر محتوا به WAV تبدیل شدند و یک فایل مفقود با TTS بازتولید شد.
- تست AudioSocket داخلی ۲، اولین صدای قابل‌شنیدن را در ۱۹۷ میلی‌ثانیه و ۱۸۵ فریم قابل‌شنیدن ثبت کرد.
- Health Check مستقیم API و داشبورد و ماژول AudioSocket پس از انتشار کنترل شدند.
- policy هر چهار کانتینر `unless-stopped` است و ایمیج‌های قبلی با tagهای `before-940ce28` برای rollback نگهداری می‌شوند.

## تلفن و بازگشت

contextهای `arka-main`، `arka-ai` و داخلی تست پذیرش `9000` در Asterisk فعال‌اند.
مقصد AudioSocket قدیمی `192.168.10.175:9092` به worker محلی ایزابل یعنی
`127.0.0.1:9092` تغییر کرد. مسیر ورودی DID عمومی در این استقرار تغییر داده نشد تا
تماس‌های جاری شرکت بدون تأیید صریح جابه‌جا نشوند.


این بکاپ شامل dump دیتابیس محلی، uploads، environment و نسخه قبل/بعد dialplan است.

## راه‌اندازی خودکار پس از reboot

واحد systemd با نام `arka-call-center.service` روی سرور نصب، فعال و با restart کنترل‌شده
تست شده است. این واحد بعد از آماده‌شدن شبکه و Docker، استک Compose را از مسیر
`/opt/arka-call-center` بالا می‌آورد. نمونه قابل نصب آن در
[`systemd/arka-call-center.service`](../systemd/arka-call-center.service) نگهداری می‌شود.

وضعیت مورد انتظار:

```bash
systemctl is-enabled arka-call-center.service  # enabled
systemctl is-active arka-call-center.service   # active
```

## مدیریت سوپرادمین‌ها

در تب «کاربران» پنل سوپرادمین امکان ایجاد حساب مدیریتی با شماره موبایل و ارتقای کاربر
موجود به نقش `SuperAdmin` اضافه شده است. حساب جدید با همان فرایند OTP وارد می‌شود و
کاربر ارتقایافته برای دریافت claim نقش جدید باید یک بار دوباره وارد سامانه شود.

APIهای متناظر فقط با نقش `SuperAdmin` قابل فراخوانی‌اند:

```text
POST /api/admin/users/super-admins
PUT  /api/admin/users/{id}/role
```

ایجاد/ارتقای نقش در لاگ عملیاتی API ثبت می‌شود. پنل همچنین از غیرفعال‌کردن حساب
سوپرادمین جاری و آخرین سوپرادمین فعال جلوگیری می‌کند.
