# گزارش پذیرش مسیر سؤال‌وجواب صوتی

تاریخ اجرا: ۲۰۲۶-۰۸-۲۶  
وضعیت: کاندید آمادهٔ انتشار؛ هنوز روی `callcenterai.ir` مستقر نشده است.

## محدودهٔ بررسی

مسیر فعال تماس به‌صورت زیر آزموده شد:

```text
AudioSocket 8kHz PCM
  -> VAD محلی
  -> Whisper /v1/audio/transcriptions
  -> GapGPT cleaner (gemini-3.6-flash)
  -> تطبیق سؤال ثبت‌شده
  -> پخش WAV ثابت پاسخ یا fallback
  -> ثبت transcript، سؤال بی‌پاسخ و فایل ضبط تماس
```

آزمون‌ها روی Docker محلی و کپی منطقی دیتابیس Production اجرا شدند. سرویس‌ها فقط روی
`127.0.0.1` منتشر شدند و هیچ migration یا تغییر داده‌ای روی دیتابیس اصلی سرور انجام نشد.

## نتیجه‌ها

| بررسی | نتیجه |
|---|---|
| تست‌های Backend | ۳۶۸ از ۳۶۸ موفق |
| lint فرانت‌اند | موفق؛ فقط دو warning قدیمی خارج از این تغییر باقی است |
| build فرانت‌اند | موفق |
| build ایمیج‌های API، Web و Realtime | موفق |
| Migration روی کپی دیتابیس Production | موفق؛ ۱۳ migration و بدون تغییر محتوای قدیمی پایگاه دانش |
| سلامت Whisper داخلی | موفق؛ مدل `whisper-1`/large-v3-turbo و زبان فارسی |
| cleaner واقعی GapGPT | موفق |
| TTS واقعی GapGPT | مسیر `/v1/audio/speech` با مدل `gemini-2.5-pro-preview-tts` و صدای `Kore` موفق |
| endpoint بومی `:generateContent` | HTTP 200 ولی بدون بخش صوتی؛ پیاده‌سازی ابتدا مسیر سازگار و سپس fallback را امتحان می‌کند |
| CRUD سؤال‌وجواب | ایجاد، ویرایش سؤال، ویرایش پاسخ، حذف، بازتولید و صفحه‌بندی موفق |
| پخش صوت داشبورد | دریافت با JWT و پخش با یک کلیک موفق؛ محدودیت autoplay کلیک اول اصلاح شد |
| AudioSocket انتها‌به‌انتها | موفق |
| سؤال تطبیق‌یافته | متن خروجی دوباره با Whisper کنترل و پاسخ درست تأیید شد |
| سؤال ناموجود | fallback اختصاصی پخش و سؤال در `UnansweredQuestionsJson` ثبت شد |
| سکوت | هیچ providerی فراخوانی نشد، صوت اشتباه پخش نشد و unanswered ثبت نشد |
| خطای Whisper/provider | پیام موقت مناسب پخش شد؛ `outcome=service_error` و unanswered ثبت نشد |
| ضبط تماس | WAV با PCM16 mono 8kHz ذخیره و مسیر آن در `CallSessions.RecordingPath` ثبت شد |
| barge-in هم‌زمان | generation guard اضافه و با تست پروتکل پوشش داده شد |

نمونهٔ پذیرش انتها‌به‌انتها:

- سؤال تشخیص‌داده‌شده: «کلاس‌های تستی از چه ساعتی شروع می‌شوند؟»
- سؤال ثبت‌شدهٔ تطبیق‌یافته: همان سؤال با `matchScore=1`
- پاسخ صوتی بازشناسی‌شده: «کلاس‌های آزمایشی از ساعت نه تا یازده صبح برگزار می‌شوند»
- تماس ثبت‌شده: `AnsweredFromKb=true`، caller و داخلی، transcript ساختاریافته و فایل ضبط موجود

## روش اجرای دوبارهٔ smoke test

پس از بالا آمدن Worker آزمایشی روی پورت دلخواه، یک WAV از گفتار تماس‌گیرنده با فرمت
PCM16 mono 8kHz آماده کنید و اجرا کنید:

```powershell
python scripts/test-qa-audiosocket.py `
  --host 127.0.0.1 `
  --port 19092 `
  --extension 178 `
  --input C:\temp\question.wav `
  --output C:\temp\response.wav
```

برای آزمون سکوت از `--expect-silence` استفاده کنید. اسکریپت UUID مطابق قرارداد dialplan
می‌سازد، فریم‌های ۲۰ میلی‌ثانیه‌ای می‌فرستد، پاسخ را جمع می‌کند و وجود/نبود صوت قابل شنیدن
را کنترل می‌کند.

## معیار انتشار

کد فعلی از نظر build، migration، provider، رابط داشبورد و پروتکل AudioSocket آماده است.
پس از تأیید مالک محصول، استقرار باید طبق `deployment.md` انجام شود و سپس یک تماس پذیرش
واقعی از Asterisk/خط تلفن اجرا گردد. این تماس نهایی پس از استقرار، تست اتصال تجهیزات واقعی
است و جایگزین آزمون‌های ایزولهٔ این گزارش نیست.

هیچ API key یا رمز عبوری در این سند، کد یا خروجی‌های قابل commit ذخیره نشده است.
