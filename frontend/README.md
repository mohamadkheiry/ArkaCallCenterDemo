# داشبورد کال‌سنتر آرکا

رابط فارسی راست‌چین با React 19، TypeScript، Vite، Tailwind و Vazirmatn محلی.
نسخهٔ فعلی همچنان از پایگاه دانش متن/فایل استفاده می‌کند.

## اجرا و بررسی

```sh
npm ci
npm run dev -- --host 127.0.0.1
npm run build
npm run lint
npm run preview -- --host 127.0.0.1
```

API توسعه در `http://localhost:5080` است. مسیرهای `/api` و `/health` در `vite.config.ts`
پروکسی می‌شوند. خروجی قابل انتشار در `dist` است؛ آن را با Vite preview یا Nginx بررسی
کنید تا مسیر فونت‌ها و bundleها نیز دقیقاً شبیه خروجی production باشند.

## نگه‌داری پخش فایل‌های صوتی محافظت‌شده

`AudioPlayButton` در تماس‌های کاربر، مکالمه‌های سوپرادمین و صوت سؤال‌های بی‌پاسخ
مشترک است. دریافت فایل همچنان با Axios و هدر JWT انجام می‌شود؛ هیچ token در URL
قرار نمی‌گیرد و endpointها عمومی نشده‌اند. فایل فقط با کلیک کاربر دریافت و تا زمانی
که همان پخش‌کننده روی صفحه است، برای توقف/ادامه/پخش مجدد در حافظه نگه‌داری می‌شود.

- منابع مرورگر (`Audio`، Blob URL و `AbortController`) در ref هستند، نه state نمایشی.
  پاک‌سازی فقط هنگام خروج پخش‌کننده، تغییر `path` یا خرابی واقعی فایل انجام می‌شود.
- **رگرسیون مهم:** به‌روزرسانی state مربوط به Blob URL نباید effectای با cleanup شامل
  `pause()` را اجرا کند؛ این الگو پخش اول را با `AbortError` قطع می‌کرد ولی کلیک دوم
  به‌علت ثابت‌بودن URL موفق می‌شد. خطا را با retry خودکار مخفی نکنید.
- قفل درخواست از لحظه کلیک تا پایان دریافت و شروع واقعی پخش فعال است؛ در این مدت
  دکمه `aria-busy` و متن «بارگذاری…» دارد. نمایش «توقف» از رخداد `playing` می‌آید.
- خروج هنگام دریافت، درخواست را cancel می‌کند؛ فایل دیررس نباید خودکار پخش شود.
  خروج هنگام پخش، صدا را قطع، handlerها را جدا و Blob URL را آزاد می‌کند.
- فایل نامعتبر/خراب در cache باقی نمی‌ماند تا تلاش مجدد بتواند نسخه سالم را بگیرد.
  رفتار 401 و خروج از حساب بدون تغییر است.

برای تست رگرسیون، روی خروجی `npm run build` در مرورگر تازه، یک WAV مصنوعی معتبر
را در پاسخ API شبیه‌سازی کنید؛ سپس با تأخیرهای صفر، ۳۰۰ و ۱۸۰۰ میلی‌ثانیه، **تنها یک
کلیک** انجام دهید. موفقیت را با پیشرفت `HTMLAudioElement.currentTime`، نبود `AbortError`
و نمایش «توقف» بررسی کنید؛ صرف تغییر آیکون کافی نیست. توقف/ادامه، پایان/پخش مجدد،
فیلتر و بازگشت ردیف، خروج حین دریافت، صوت سؤال بی‌پاسخ، پنل ادمین، موبایل و بازیابی از
404/502/قطع شبکه/فایل غیرصوتی/فایل خراب/401 نیز باید بررسی شوند. در بررسی ۲۰۲۶-۰۹-۰۵
هر ۱۷ سناریو در Chrome با Playwright موفق بود. این تست با داده مصنوعی است و به‌معنی
شنیدن محتوای خصوصی تماس‌های Production یا تست روی گوشی واقعی نیست.
